УСТРОЙСТВО ПРОЕКТА
Практическая работа № 2, вариант 8, C++17

1. НАЗНАЧЕНИЕ

Пакет — опубликованный программный модуль. npm — экосистема пакетов
JavaScript. Анализатор написан на C++: язык инструмента и язык пакетов
не обязаны совпадать.

Пользователь задаёт имя пакета и точную версию. Программа получает
JSON-метаданные, выбирает версии зависимостей, строит граф, сохраняет
описание DOT и изображение SVG. Флаг --ascii включает дерево в терминале.

Вершина — конкретная версия пакета: chalk@4.1.2. Ребро A -> B означает,
что A использует B. Прямая зависимость указана непосредственно у A;
транзитивная достигается через другие пакеты. Разные версии одного пакета
являются разными вершинами.

Приложение читает метаданные, не устанавливает пакеты и не запускает их код.
Graphviz получает готовые связи и рисует граф. npm используется отдельно
только для сравнения результата, предусмотренного заданием.

2. ПЯТЬ ЭТАПОВ

1 — параметры командной строки, значения по умолчанию, проверка ошибок.
2 — получение метаданных и прямых зависимостей.
3 — выбор версий и полный граф рекурсивным BFS.
4 — поиск прямых и косвенных обратных зависимостей.
5 — DOT, SVG, ASCII-дерево, сравнение трёх пакетов с npm.

Каждый этап добавляется отдельным коммитом. Итоговый обычный запуск
уже создаёт SVG. Поведение второго этапа доступно через --direct,
четвёртого — через --reverse.

3. ПОСЛЕДОВАТЕЛЬНОСТЬ ЗАПУСКА

run.bat -> build.ps1 -> CMake -> visual_graph_tool.exe
  -> parse_arguments -> validate_config
  -> NpmRepository или TestRepository -> корневой Package
  -> build_graph -> save_visualization -> DOT -> Graphviz -> SVG
  -> print_graph или print_ascii

Для --direct после чтения корня вызывается print_dependencies без обхода.
Для --reverse после обхода вызываются reverse_graph и print_reverse.
В этих режимах файлы не создаются, --ascii не меняет их текстовый вывод.
Для --help выводится справка; пакет и версия не требуются.
При исключении run печатает ошибку в stderr и возвращает 2, при успехе — 0.

4. ВСЕ ФАЙЛЫ И ИХ ОТВЕТСТВЕННОСТЬ

src/app.hpp
Общие структуры и объявления функций — договор между модулями.
#pragma once защищает от повторного включения заголовка при компиляции.

src/main.cpp
Точка входа и выбор действий. wmain получает Unicode-аргументы Windows
и переводит их в UTF-8. process выбирает источник, show_result — режим,
show_graph — способ вывода. run перехватывает ошибки.

src/config.cpp
Разбор опций и проверка имён, версии, URL, тестового файла, выходного пути,
фильтра и цели --reverse. print_help печатает справку. print_config
сохранена от этапа 1 и проверяется тестами; обычный запуск её не вызывает.

src/data.cpp
Собственный JSON-парсер, кодирование URL, HTTP через WinHTTP, проверка
метаданных, загрузка корневого пакета, чтение тестового репозитория.

src/graph.cpp
Сравнение версий и диапазонов, выбор версии зависимости, кеширование,
рекурсивный BFS, фильтрация, разворот рёбер и текстовые отчёты.

src/visualization.cpp
Описание DOT, дерево ASCII, запуск dot.exe, сохранение SVG.
Временные файлы отделяют рендеринг от замены готового результата.

tests/unit_tests.cpp
Модульные проверки параметров, JSON, версий, графов, DOT и ASCII.
Вместо настоящих сетевых запросов передаются функции с готовыми ответами.

tests/test_cli.cpp
Проверки настоящего приложения, запущенного отдельным процессом.
HTTP-сервер на 127.0.0.1 возвращает тестовые метаданные и ошибки.
Проверяются stdout, stderr, код завершения, файлы, работа Graphviz.

tests/test_support.hpp
Общие средства тестов: check, expect_error, чтение файлов, преобразование
JSON и TestSuite. При провале одной проверки остальные продолжаются;
в конце выводится число успешных проверок и ошибок.

examples/repository.json
Вход для --test-mode. A — ветвление с общей зависимостью D;
X — цикл X -> Y -> Z -> X; I — изолированный узел; S — петля.

examples/metadata.json
Сохранённые метаданные настоящих пакетов и ссылки на источники.
Их используют автоматические тесты. Это не формат --test-mode.

CMakeLists.txt
Настройки C++17 и сборки. graph_tool — библиотека общего кода,
visual_graph_tool — приложение, unit_tests и cli_tests — тестовые программы.
CTest запускает две группы. CMake также ищет dot.exe.

build.ps1
Находит CMake в PATH или в Visual Studio, настраивает и выполняет сборку
Debug. С флагом -RunTests запускает CTest.

run.bat
Вызывает сборку, прекращает работу при её ошибке, находит EXE и передаёт
все аргументы через %*. Сообщения сборки идут в stderr, чтобы stdout
содержал только результат самого анализатора.

.gitignore
Исключает build, двоичные файлы, настройки редактора и результаты SVG/DOT.
Инструменты build/tools и результаты build/demo не публикуются.

.gitattributes
Задаёт окончания строк: LF для исходников, CRLF для Windows-скриптов.

README.md
Краткие команды и ссылки на материалы. docs/01_project.txt — устройство;
02_algorithms.txt — алгоритмы; 03_defense.txt — демонстрация и вопросы.

5. ОСНОВНЫЕ СТРУКТУРЫ

Config — настройки запуска.
Json — тип значения и поля text, items, members.
Package — имя, точная версия, словарь dependencies: имя -> диапазон.
Version — три числа major/minor/patch и части предварительной версии.
VersionRange — альтернативные группы условий сравнения.
DependencyGraph — root, order (порядок BFS), edges (списки соседей).
GraphLimits — ограничения числа вершин и глубины.

NpmRepository читает реестр; TestRepository читает тестовый JSON.
Fetch — функция URL -> текст ответа.
Resolve — функция имя + диапазон -> Package.
Подмена функций позволяет проверять алгоритмы без интернета.

6. ПАРАМЕТРЫ

--package ИМЯ       Обязательное имя корневого пакета.
--version ВЕРСИЯ    Обязательная точная версия, например 4.1.2.
--repository ПУТЬ   По умолчанию https://registry.npmjs.org.
--test-mode         Читать JSON-файл из --repository вместо HTTP.
--output ФАЙЛ.svg   По умолчанию graph.svg; рядом создаётся graph.dot.
--ascii             Дерево вместо списка рёбер и порядка BFS.
--filter ТЕКСТ      Исключать имена с указанной подстрокой.
--direct            Только прямые зависимости без обхода и изображения.
--reverse ПАКЕТ     Найти зависимые от него пакеты в корневом графе.
--help или -h       Справка.

Значение задаётся через пробел или =. Флаги значений не принимают.
Неизвестная опция, повтор и пропуск значения считаются ошибками.
--reverse допускает имя@версия; при нескольких версиях это обязательно.
--reverse несовместим с --direct. Фильтр применяется до обратного поиска
и чувствителен к регистру. Другой путь может сохранить достижимость потомка
исключённого узла.

Корневая версия точная: --version latest или ^4.0.0 не допускаются.
Диапазоны используются у зависимостей, прочитанных из метаданных.
В тестовом режиме имена состоят из заглавных латинских букв, всем узлам
назначается версия, указанная пользователем.

7. ЧТО НУЖНО ПОНИМАТЬ В C++

struct объединяет данные; class дополнительно скрывает детали реализации.
vector — последовательность, map — словарь, set — множество без повторов.
map сортирует ключи, поэтому порядок обработки зависимостей воспроизводим.
const T& передаёт объект без копирования и запрещает его изменение.
auto выводит статический тип из выражения, а не отменяет типизацию.
optional содержит значение или отсутствие значения.
Лямбда — небольшая функция; [&] захватывает окружающие объекты по ссылке.
function позволяет передать такую функцию в общий алгоритм.
move разрешает перенос содержимого вместо лишнего копирования.

throw сообщает об ошибке, catch её перехватывает. RAII означает освобождение
ресурса при уничтожении объекта: так закрываются HTTP-дескрипторы, файлы,
процессы; TemporaryFiles удаляет временные данные. Это действует и при ошибке.

namespace graph_tool объединяет имена проекта; безымянный namespace скрывает
вспомогательные функции внутри .cpp. #ifdef выбирает код для Windows.
Используются шаблоны стандартных контейнеров; собственных шаблонных функций
запуска приложению не требуется.
